# 市集筛选与作品管理

公开市集 `/marketplace` 与编辑器内市集支持相同的复杂程度筛选：

- 豆子数量：≤ 500、501–2,000、2,001–5,000、> 5,000。
- 颜色数量：≤ 5、6–15、> 15。
- 同色连续程度：分散（< 50%）、适中（50–79%）、连续（≥ 80%）。
- 排序：最新、豆子更少、颜色更少、同色更连续。

连续程度按可见图层合成后的二维图案计算：所有横向及纵向相邻、两格都有豆子的配对中，同色配对所占的百分比，四舍五入到整数。每对只计算一次；空格和对角线不计，没有相邻配对的图案为 0%。此指标表示相邻颜色的一致程度，不是完整的制作难度评分；可结合颗数和颜色数判断。

## 数据库升级

按顺序执行已有迁移，再执行 `supabase/migrations/202610200003_marketplace_management.sql`，然后部署新版应用。新迁移给已有作品默认设为已上架，并回填颗数、颜色数和连续程度；之后在图案写入／修改时由数据库触发器自动计算。更新列表 RPC 签名以支持筛选、排序与管理员可见性。

迁移包含一次全量回填，作品较多时请预留执行时间。应用依赖新字段及 RPC，须先完成迁移。不要将服务端 Supabase 密钥放入前端配置。

## 管理入口

继续使用服务端 `ADMIN_USERNAMES`（逗号分隔、不区分大小写）配置管理员。管理员登录后，账号区域显示“市集管理”，进入 `/admin/patterns`（英文 `/en/admin/patterns`）。

- 作品概览：全部、已上架、已下架数量，点击数字可查看对应列表。
- 作品管理：按标题／作者／介绍搜索，按上架状态筛选，分页查看预览和指标。
- 编辑：修改名称、分类、介绍，保留原作者和原图案。
- 下架／重新上架：保留作品以便恢复。下架作品不出现在公开列表、站点地图，公开详情、预览及图纸接口返回 404。公开市集页、作品详情及预览采用 `no-store`，避免新响应被缓存而延迟反映管理操作；部署前已缓存的旧内容仍受原缓存期限约束。

管理页面不嵌入作品数据。管理 API 每次检查服务器会话和管理员权限，未授权返回 403，跨站修改请求被拒绝。

接口：`GET /api/admin/patterns?page=1&limit=24&status=all&q=...`；`POST /api/admin/patterns/:id` 仅允许修改 `title`、`description`、`category`、`status`。公开 `GET /api/patterns` 支持 `beads`、`colors`、`continuity` 和 `sort`，筛选作用于完整数据集后再分页。

## 分类管理

在“市集管理 → 分类管理”新增分类，修改中文名称／可选英文名称、排序值，或停用／重新启用。排序值为 0–9999，越小越靠前。

上线前在复杂程度和作品管理迁移之后执行 `supabase/migrations/202610200004_marketplace_categories.sql`。迁移会初始化原有五种分类，把原有的固定分类约束替换为分类表外键。分类重命名会在同一事务中同步更新所有关联作品（包括已下架作品）。已有作品保留分类关联，停用不删除分类或作品。

公开市集筛选、作品详情、编辑器市集、投稿和管理员作品编辑均从分类接口读取目录。停用的分类仍可用于筛选历史作品；普通投稿只能使用启用中的分类。所有分类均停用时，投稿入口不可提交，管理员可重新启用。管理员仍可给已有作品调整到任意已存在的分类。

`GET /api/categories` 返回按显示顺序排列的分类；管理员可用 `GET /api/admin/categories`，以及 `POST /api/admin/categories` 新增、`POST /api/admin/categories/:id` 更新。字段为 `name`（1–20 字，不能为“全部”，忽略大小写唯一）、`nameEn`（最多 60 字）、`sortOrder`（整数）、`active`（布尔值）。修改接口只接受这些字段，所有修改均检查会话、管理员权限和同源来源。
